## What 1.0 means

A researcher who has never heard of Infall downloads it, opens it without a security warning, puts a real project into it, loses nothing, and can bring their lab in later. Concretely, 1.0 is reached when every line below is true:

1. Installers for macOS, Windows and Ubuntu open without a warning and update themselves.
2. Every feature has been seen working in the packaged app on all three systems, not only in tests.
3. A Local Workspace can be moved onto a team's server.
4. A slip on the Board or a Page is undone with Cmd/Ctrl+Z.
5. A Board of 2 000 Cards and a Page of 50 screens stay usable.
6. Someone who is not us has installed a Team server from the docs alone.
7. Three researchers have used it on real work for two weeks, and what stopped them is fixed.
8. The screens built without a designer have been through the design pass and approved.

## Where we are

Built: Board, Cards, Frames, Connections, Pages, Sources, Visuals, Runs and the Runner, Branches, Merge, History and Restore, To-dos, AI sidebar and Suggestions, Guests, Team server, desktop app with the server inside it, Local Workspaces, Presets, the hands-on Tutorial, the Tour, Settings, Workspace files and backups, Markdown/BibTeX export, BibTeX import, Look up.

Facts checked today that shape the plan:

- **No undo on the Board.** There is no Cmd/Ctrl+Z handling outside text fields. History and Restore exist but are too heavy for a slip.
- **No updater**, no code signing, no licence file.
- **The repository has no remote.** The only copy of the code is this computer.
- Windows and Linux have not been built or run since M11. The `.exe` and `.deb` files in `dist/` are stale.
- M12's later parts and all of M13 were verified by tests and, on macOS, partly by hand; most of their screens have not been seen in the packaged app.
- Known small defects: the window scrolls sideways at interface scale 150 % in a 900 px window; all Local Workspaces share one session cookie; a hand copy of a Workspace's database cannot be imported; exported BibTeX titles lose case protection.

### Research routes as Suggestions

Today an AI can propose only a Source or a Connection. This lets it propose where the research could go next: a hypothesis, an open question, a next experiment — and a whole route (a few Cards with their Connections, in a Frame) — for a Member to accept or reject.

- **New kinds of Suggestion**: a Card, and a route (a Frame with a few Cards and Connections). Each carries its reason and what it rests on: the Cards, Sources and PDF pages it was drawn from, so a Member can judge it.
- **Asking for them**: an action on the Board or on a Frame ("Suggest directions") — the AI reads that part of the Research Content and answers with three to five routes as pending Suggestions.
- **Accepting**: puts the route on the Board, by default on a new Branch so that main stays as it is. Rejecting drops it. As with every Suggestion, nothing becomes Research Content until a Member accepts it.
- **No new model plumbing**: it goes through the existing tool layer and the Member's own subscription (ADR 0003).

Needs a grilling before a spec: what a route is in CONTEXT.md's words (the glossary's Suggestion is "a Source or Connection" and must be widened); where an accepted route lands; how many at once; how it is kept from repeating what is already on the Board. About one milestone: the tool layer and the accept ops (`crates/**`), the Suggestions panel and the Board action (`web/**`), the instructions the AI is given.

### Repositories, maps of code, and agents that write it

Added 26 November 2026 by the owner's decision, after a brainstorm the same day; to be built after route Suggestions, whose machinery it reuses. Why: when the owner works through research with Claude outside Infall, Claude builds the repository and draws what interacts with what and why it matters. That picture then stays behind in a chat. It should be made, kept and tied to the findings inside Infall.

Four builds, each resting on the one before. The first two are useful on their own.

1. **A repository, and a Card that points into it.** A Workspace names a repository; each Member says, per device, where their own checkout of it is (the way an Environment is a name each device resolves). A Card can point at code: a path, a function or lines, and the commit it was at, with the few lines kept as they were so that a Member with no checkout, in a browser, still sees them. **Open in editor** hands the place to the Member's own editor. When the code has changed since, the Card says so, as a Run does for its code; and from a file, the Cards that rest on it can be listed. No file manager: only enough of a viewer to show the place pointed at.
2. **A map of the code as a Suggestion.** The AI reads a repository and proposes a Frame of Cards (the parts, each with what it does and why it matters) and labelled Connections (what feeds what), joined to the finding Cards that rest on them. This is a route Suggestion with code behind its Cards: built once, with the section above. The map records the commit it was drawn at, says when the repository has moved on, and an update proposes only the differences, leaving what a Member changed by hand.
3. **Agents.** An agent is a set of instructions, what it reads, and one of three powers that the desktop app enforces and the instructions cannot widen: talk only; make Suggestions; write code. "Suggest directions", the map and the Engineer below are agents that come with Infall; others (one that argues against a Card from its Sources, one that reads a Page as a referee) are the same shape with other instructions. A Member's own agent starts as a copy of one of these with its instructions edited. Claude Code's own agent files are the format to bring one in or take one out.
4. **The Engineer.** The first agent, by the owner's choice: the sidebar writes code in the repository and runs it, then returns the map of what it built as Suggestions.

**Decided by the owner on 26 November 2026:**

- The sidebar writes code. This moves a rule that desktop.md ("every built-in tool disabled") and api.md §15 ("AI cannot put code on anyone's machine") state today.
- It runs what it writes, under modes like Claude Code's that the Member chooses: asking first, or by itself. The Member's agreement to the mode is the guard; no sandbox ("a sandbox for Runs" stays in the list above).
- The Engineer comes before the other agents.

**Proposed, not yet decided:**

- The Engineer works in a separate working copy on a git branch of its own, so the Member's files are untouched until they keep the result (a merge) or discard it. Infall never pushes.
- The mode is chosen in a window of the app's own, like the Runner's approval, never by the page: the page comes from a server, and a page that could switch to "by itself" would make the agreement worth nothing.
- When working by itself, the Engineer reads only the Cards the Member pointed it at, not the whole Board: the text on a Board, in a PDF or in a looked-up Source was written by other people and other AIs, and the Member agreed to the mode, not to that text. In a Local Workspace, where all of it is the Member's own, this matters least; so a Local Workspace first.
- Files that git ignores are not read, so that nothing kept out of the repository ends up on a Board.
- An agent shared in a Team Workspace that may write code shows its instructions before its first use and after any change, as a Run shows its code.
- A Run's result records the commit of the repository it was executed in.

**What stays as it is:** the server executes nothing; no tool creates a Run or changes its code, so AI-written code reaches another Member only through git, by their own pull; AI never writes Research Content directly, only Suggestions and what a Member Pins (ADR 0003); a browser has no machine, so writing code is the desktop app's alone.

**Left out on purpose:** a file tree and editor inside Infall (the Member's editor does it better); Comment threads on lines of a file (a remark about research belongs on the Card that points at the code); a map drawn from imports alone; repository files as Research Content (git stays git).
